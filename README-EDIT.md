# 凭密码编辑文章 · 安全设计说明

> 本文档说明 daydream-room 博客「每篇文章凭密码编辑」功能的威胁模型、
> 安全决策与运维方式。对应代码：`src/lib/security/`、`src/lib/editPosts.ts`、
> `src/app/api/posts/**`、`src/components/PostEditPanel.tsx`、
> 共享契约 `src/lib/edit-contract.ts`。

## 一、三个不可动摇的设计前提

1. **Fail-closed（失效即拒绝）**：密码校验、会话检查、权限判断在任何异常
   （数据库连不上、哈希损坏、配置缺失、JSON 解析失败）下都走向拒绝。
   代码中所有 API 路由的外层 `try/catch` 一律返回 500 拒绝，绝无
   「异常后继续执行写操作」的路径。
2. **最小权限**：编辑密码只换取「编辑这一篇文章」的短时效令牌。解锁后
   不能删除文章、不能改发布状态、不能上传文件、不能改站点设置——
   每一个敏感操作都是独立校验的独立接口。
3. **不信任客户端标识符**：文章 slug、令牌、隐藏字段全是攻击者可任意
   修改的输入。**每一次**保存/恢复/锁定请求，服务端都从零开始独立判断：
   这个令牌是否有效、是否绑定这篇文章、作用域是否为 edit。

## 二、密码安全

| 项 | 实现 |
|---|---|
| 哈希算法 | **Argon2id**（`@node-rs/argon2`，OWASP 参数 m=19456 KiB / t=2 / p=1），内存硬、抗 GPU/ASIC |
| 盐 | Argon2id 内置独立随机盐，每密码唯一 |
| 存储 | 仅存哈希（`db/custom.db` 的 `EditSetting` 表），绝不明文、绝不用 MD5/SHA 系快速哈希 |
| 校验 | argon2 `verify`（常量时间语义）；verify 异常（哈希损坏）→ false（fail-closed） |
| 策略 | 长度优先：12–128 字符，不强制复杂度组合 |
| DoS 防护 | >512 字符的密码输入直接早拒，不进慢哈希 |

编辑口令由站长在服务端固定设置（`scripts/seed-edit-password.mjs`，哈希入库、
明文不落盘）。**站点不提供改密 / 忘记密码入口** —— 解锁对话框只有
「输入口令 → 解锁」一步，无任何口令管理功能面。也支持环境变量
`EDIT_PASSWORD` 在首次解锁时自动完成初始化（同样走哈希入库，明文不落盘）。

## 三、认证流程：密码只用来「换令牌」

```
输入密码 → POST /api/posts/<slug>/unlock
        → 服务端验证 Argon2id 哈希
        → 颁发 32 字节随机编辑令牌（HttpOnly Cookie）
        → 后续保存只携带令牌 + CSRF 头，密码不再传输
```

**令牌属性**（`EditToken` 表）：
- **短 TTL**：绝对有效期 30 分钟；**空闲超时** 15 分钟无操作即失效
- **一次性旋转**：每次保存/恢复成功 → 旧令牌即刻消费作废 → 签发新令牌
  （响应体携带新 CSRF，前端立即替换）
- **只存哈希**：数据库存令牌与 CSRF 的 SHA-256，泄露也无法重放
- **绑定对象**：每条令牌记录 `slug` 与 `scope="edit"` —— 一个令牌绝不能
  编辑另一篇文章
- **Cookie**：`HttpOnly` + `SameSite=Lax` + `Path=/` + `Max-Age=1800`，
  网关 HTTPS 下自动加 `Secure`；浏览器关闭/锁定/改密码均失效

## 四、授权：对象级检查（防 IDOR 核心）

每次写请求的服务端判定顺序（`requireEditAuthz`）：

```
无 cookie → 拒            无 CSRF 头 → 拒
令牌哈希查无 → 拒          已吊销/已消费 → 拒
绝对过期 → 拒（顺手吊销）   空闲超时 → 拒（顺手吊销）
scope ≠ "edit" → 拒        令牌绑定 slug ≠ 目标 slug → 拒   ← IDOR 防线
CSRF 哈希非常量时间相等 → 拒
全部通过 → 更新 lastUsedAt → 放行本次写入
```

**已验证**：解锁文章 A 的令牌拿去保存文章 B → 403，B 毫发无损。
UUID/不可猜测 ID 只是辅助，从不当作访问控制本身。

## 五、限速与防枚举

- **按 IP**：60 秒内 5 次失败 → 指数锁定（300s×2ⁿ，上限 1 小时）
- **按文章**：同一 slug 600 秒内 20 次失败（不论来源 IP）→ 全局锁 600 秒，
  防分布式 IP 轮换绕过
- **统一失败文案**：「文章不存在 / 密码错误 / 未配置密码」一律返回同一
  错误码 `unlock_failed` 与同一句话；「令牌过期 / 越权 / CSRF 失败」一律
  `session_invalid` —— 客户端无法用来枚举
- 成功解锁即重置对应计数器

## 六、输入与输出

- **SQL 注入**：全部经 Prisma 参数化查询，无拼接
- **XSS**：编辑器是**结构化纯文本块模型**（段落/小标题/金句三选一 + 文本），
  不引入任何 HTML —— 输出走 React 文本节点自动转义，等价于只允许
  p/h2/quote 的 allow-list sanitizer，且更彻底。服务端另有 zod 白名单
  （类型枚举、块数 ≤100、单块 ≤5000 字）+ 控制字符剥离 + 100KB 请求体上限。
  已实测：`<script>alert(1)</script>` 被原样存为纯文本，渲染为转义文字。
- **CSRF**：写操作全 POST + `content-type: application/json` 强校验（跨站
  表单发不出 JSON）+ 双重提交 CSRF（`x-csrf-token` 头与令牌记录的哈希
  常量时间比对）+ `SameSite=Lax` Cookie 三层纵深

## 七、文件上传

本功能**不提供**任何文件上传能力（编辑会话也不隐含上传权限），
对应攻击面为零。未来若加配图，需按白名单扩展名/MIME、服务端随机文件名、
路径规范化、上传目录禁执行、独立限速另行评审。

## 八、会话与状态

- 解锁状态不持久化（无「记住我」），关页即弃
- 保存成功 → 令牌旋转，旧令牌即刻作废
- 主动「锁定会话」→ 全量吊销未过期令牌
- 空闲 15 分钟 / 绝对 30 分钟双保险

## 九、日志与监控

`AuditLog` 表记录：解锁尝试（成败/原因码）、保存、恢复、锁定、令牌旋转，
含 slug、IP、令牌哈希前 8 位（关联用）。

**绝不记录**：密码明文、密码哈希、令牌明文、CSRF 明文。
（已实测：审计全表检索不到任何敏感料。）

日志随 SQLite 库存储，读取面 = 能读库的人；如需更高保障可外发站外。
建议关注的告警信号：短时间同 IP 或同 slug 大量 `unlock_fail`。

## 十、运行与运维

```bash
bun install
bun run db:push                                # 建表
bun scripts/seed-edit-password.mjs --set 口令    # 初始化编辑口令（哈希入库，明文不落盘）
bun run dev                                    # 起服务
```

- 口令在服务端固定（本站已按站长指定口令初始化完毕）；站点无改密 /
  忘记密码入口，前端不暴露任何口令管理功能
- 已知边界：限速器为**单实例内存版**（模块级 Map）——当前 standalone
  单实例部署无影响；若未来水平扩展需换 Redis 等共享存储
- `EDIT_PASSWORD` 环境变量仅在「库里还没有哈希」时用于首次初始化

- [x] Argon2id（OWASP 参数）+ 独立盐；verify 常量时间语义

- [x] 解锁按 IP + 按文章双维度限速
- [x] 失败响应不区分文章不存在/密码错误/令牌过期
- [x] 密码验证通过后颁发短期令牌，密码不再传输
- [x] 令牌只存哈希；绑定 slug 与 edit 作用域
- [x] TTL 30 分钟 + 空闲 15 分钟
- [x] Cookie HttpOnly / SameSite=Lax /（HTTPS 或生产）Secure
- [x] 保存成功即消费旧令牌并旋转
- [x] 每次写请求独立对象级授权（含 IDOR 实测）
- [x] 解锁状态不附带任何其他接口权限
- [x] Prisma 参数化查询（无 SQL 拼接）
- [x] 结构化纯文本 + React 自动转义（等价 allow-list sanitizer）
- [x] 保存全 POST + JSON content-type + CSRF 头 + SameSite
